# Demo and release workflow
Use in stabilization/release phases, not every coding task.
- Re-run the live flow (first encounter, conversation, Possession code question, time travel) and the labelled recorded fixture flow.
- Confirm real source citations, SHA isolation, approximate outlines labelled, desktop/mobile and reduced motion.
- Confirm public GitHub repo, LICENSE, root `.kiro/`, README with `DISCLOSURES.md` link, safe example env and deployment access.
- Check no secrets/trademarks/unlicensed audio or art in public release.
- Video must be public YouTube, under 3 min, functioning app visible, Kiro contribution accurately demonstrated. No quest shot (deferred, D2).
- KIRO_LOG.md holds only work done with Kiro, with evidence of outcomes; work done with other tools goes in `DISCLOSURES.md`. No fabricated tests/pilot results.
- Make precise go/no-go list with defects, owner, reproduction steps and fixes.
